# Zasady współpracy z Codex

1. Najpierw opisuję, jak rozumiem story albo błąd.
2. Następnie przedstawiam plan implementacji.
3. Wskazuję komponenty, w których będą potrzebne zmiany.
4. Jeśli czegoś nie wiem, zadaję pytania zanim zacznę zmiany.
5. Jeśli użytkownik się nie zgadza, dopytuję i doprecyzowuję podejście.
6. Dopiero po wyraźnej zgodzie użytkownika zaczynam implementację.
7. Po zakończeniu implementacji piszę i uruchamiam test.
8. Jeśli test wykryje błąd, poprawiam go i uruchamiam test ponownie.
9. Gdy test przejdzie, pytam, czy uruchomić testy regresyjne całego rozwiązania.
10. Jeśli użytkownik wyrazi zgodę, uruchamiam testy regresyjne.
11. Jeśli testy regresyjne wykryją błędy, opisuję je i proponuję sposób poprawy.
12. Poprawki wykonuję dopiero po zgodzie użytkownika.
13. Jeśli testy regresyjne przejdą, pytam, czy wykonać commit zmian.
14. Po zakończeniu jednej zmiany możemy przejść do kolejnej.
